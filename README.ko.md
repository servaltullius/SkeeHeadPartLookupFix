# SkeeHeadPartLookupFix (한국어 / 내부 메모)

영문 배포 설명은 `README.md`. 이 문서는 구현 세부와 작업 기록.

RaceMenu(skee64.dll)는 얼굴을 다시 만들 때 스컬프트를 적용한다(`Actor::DoReset3D` → `TESNPC::UpdateMorphs` 후킹 →
`FaceMorphInterface::ApplyMorphs`). 이때 얼굴 메쉬마다 `GetHeadPartByName()`으로 **모든 헤드파트를 순회하면서, 매 반복
BSFixedString 을 생성/해제**한다. 이 플러그인은 그 비용을 없앤다.

- 헤드파트 36,775개 + 스컬프트 부위 15개 기준으로 얼굴 한 번에 생성/해제 약 44만 쌍이었다.
- 세이브 로드 직후 플레이어 얼굴이 5번 다시 만들어진다.

## 지원 빌드

| RaceMenu | 게임 | 스컬프트 루프 (인라인, 앞 NOP → `call stub`) | `GetHeadPartByName` 함수 교체 (`jmp`) |
|---|---|---|---|
| 0.4.20.0 Steam | AE 1.6.1170 | skee64+0xBDDF4 (NOP 12) | skee64+0x582C0 |
| 0.4.20.0 GOG | AE 1.6.1179 (GOG) | skee64+0xBE0B9 (NOP 7) | skee64+0x58290 |
| 0.4.19.16 | AE 1.6.1170 | skee64+0xBA165 (NOP 11) | skee64+0x57F00 |
| 0.4.16 | SE 1.5.97 | — (스컬프트 람다가 함수를 호출) | skee64+0x34BE0 (호출자 5곳 전부) |

**빌드 식별**
- skee64.dll 의 PE 타임스탬프 + 이미지 크기로 고른다.
- 파일 버전으로는 구분할 수 없다.
  - 0.4.16 은 파일 버전이 3.4.5.0 으로 찍혀 있다.
  - 0.4.20.0 Steam 과 GOG 는 버전이 같다.

**바이트 검사**
- 패치가 기대는 명령의 바이트를 확인한다(AE 18곳, SE 9곳).
- 하나라도 다르면 **패치하지 않는다**. 수정된 skee64.dll 이나, 다른 플러그인이 같은 곳을 먼저 고친 경우도 포함한다.
- 덮어쓸 바이트가 검사 목록에 들어 있는지도 코드가 확인한다(`SitesAreChecked`).
- 여러 패치 지점은 모두 적용하거나 하나도 적용하지 않는다.

**스텁 배치**
- 스텁/썽크는 skee64.dll 에서 rel32 로 닿는 곳에 할당한다(`AllocExecNear`).
- 그래서 패치 지점은 5바이트 `call`/`jmp` 만 쓴다.

## 동작

- **`kPostLoad`**: 위 표에 따라 패치한다.
- **`kDataLoaded`** (패치했을 때만): `이름(ASCII 대소문자 무시) → 첫 인덱스` 맵을 만든다. 원본과 같은 첫 일치 규칙이다.
- **인라인 루프**
  - 스텁이 루프 인덱스 EBX 를 일치 인덱스로 설정한다. 원래 루프가 첫 반복에서 일치하고, 스컬프트 적용은 원래 코드가
    그대로 수행한다.
  - 일치하는 게 없으면 인덱스를 개수로 설정한다. 전수 탐색 후 불일치와 결과가 같다.
  - 맵 미준비, 헤드파트 수 변경, 슬롯 이름 불일치, 비ASCII 이름이면 인덱스 0, 즉 원래 전수 탐색으로 돌아간다.
- **`GetHeadPartByName` 함수 교체**
  - 맵으로 답한다.
  - 답할 수 없으면 원본과 같은 방식으로 찾는다. 이름을 한 번 BSFixedString 으로 만들어 풀 포인터를 비교하고, 첫 일치를
    돌려준다.

## 로그

`SkeeHeadPartLookupFix.log` (SKSE 로그 폴더).
- 시작 시 남는 줄:
  - skee64 식별(파일 버전, 타임스탬프, 크기)
  - 패치 지점마다 `patched ...`
  - `Lookup cache built ...`
- 로드 30초 뒤 한 줄(`[this load, first 30 s]`):
  - 그 로드의 캐시 적중 / 일치 없음 / 원래 방식 수
  - 피한 생성/해제 쌍(추정)
  - 카운터는 세이브 로드가 시작될 때 0으로 돌아간다. 30초 안에 다른 로드가 시작되면 이전 로드의 줄은 생략한다.

## 한계

- 위 표의 4개 빌드만 지원한다. 그 밖은 자동으로 꺼진다.
  - VR 0.4.14
  - 수정·재컴파일된 skee64.dll
  - 1.7.99 용 새 RaceMenu
- 인게임 확인은 0.4.20.0 Steam 에서만 했다(패치 코드는 2.0.0 에서 확인, 2.1.0 은 진단 제거·로그 변경만). GOG / 0.4.19.16 / 0.4.16 은 바이너리 대조(식별값·명령 바이트·분기)까지만
  확인했다.
- AE 빌드에는 같은 검색이 인라인된 곳이 3곳 더 있고 원래 방식 그대로다(0.4.20.0 Steam 기준). 프리셋 경로로 보이며
  프로파일에서 비용이 나오지 않았다.
  - +402B0 / +414D0 안의 인라인 루프: 이름이 RBP 기준 지역 변수라, 스텁에 RBP 기준 주소 지원이 필요하다.
  - +41AB0 안의 인라인 루프: 루프 앞 NOP 이 3바이트뿐이라 5바이트 call 이 안 들어간다. 다른 지점(cmp 교체)이 필요하다.
- 스컬프트 데이터가 있는 캐릭터의 얼굴 재구성에만 효과가 있다. 평균 FPS 가 아니라 재구성 때의 히치를 줄인다.
